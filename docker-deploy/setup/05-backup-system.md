The backup system provides complete data protection with intelligent retention policies, automated backups, and reliable restore capabilities.

## Backup Types

### 1. Blank Backup (Permanent)

**Purpose:** Clean installation state for system reset

**Creation:** 
```bash
./mark_blank_backup.sh
```

**Contains:**
- Fresh Dolibarr database schema
- Initial configuration after installation  
- Empty or minimal documents directory
- No business data

**Characteristics:**
- Created **once** after installation
- **Never deleted** by retention system
- Marked with `_BLANK` suffix
- Use for "factory reset" scenarios

**When to Create:**
- ✅ After completing Dolibarr installation wizard
- ✅ After setting up admin accounts
- ✅ After configuring basic settings
- ❌ Before adding customers/products/data

### 2. Daily Backups (Rolling)

**Purpose:** Regular operational backups with business data

**Creation:**
```bash
# Automatic (via daily_exit.sh)
./daily_exit.sh

# Manual
./backup_dolibarr.sh
```

**Contains:**
- Complete database with all business data
- All uploaded documents and files
- Current configuration
- Full system state

**Characteristics:**
- Created daily or on-demand
- **Last 3 kept** (older ones deleted)
- Rolling retention policy
- Named by timestamp: `dolibarr_backup_YYYYMMDD_HHMMSS`

### 3. Compliance COOS Backup (Trace-only)

**Purpose:** Compliance and provenance trace (not a full system restore)

**Creation:**
- Automatically generated by `./daily_exit.sh` alongside daily backups
- Can also be generated by `scripts/project/backup_coos.sh`

**Location:**
- Repository root: `coos_backup/`

**Contains:**
- MANIFEST.md — inventory of key artifacts
- TRACE.md — change trace, versions, timestamps
- COPYING, COPYRIGHT, ChangeLog — license and change history

**Characteristics:**
- Lightweight, append-only style record
- Complements full backups; use full backups for restoration
- Useful for audits and external reporting

## Backup Retention Policy

### Smart Retention System

The system maintains **exactly 4 backups**:

1. **1 Blank Backup** (oldest, permanent)
   - Your clean installation state
   - Never deleted automatically
   - Identified as oldest backup in retention logic

2. **3 Recent Backups** (rolling window)
   - Most recent daily backups
   - Contains all business data
   - Older backups beyond 3 are deleted

### Retention Logic Flow

```
New Backup Created
        ↓
Count Total Backups
        ↓
    More than 4?
        ↓
   ┌─── Yes ────┐         ┌─── No ────┐
   ↓            ↓         ↓           ↓
Find Oldest  Keep All  Retention   Done
(Blank) +    Backups   Complete
Newest 3         ↑         ↑
   ↓            ↓         ↓
Delete All   Success   Success
Others
   ↓
Success
```

### Example Retention Scenario

**Initial State (after creating blank backup):**
```
backups/
└── dolibarr_backup_20251025_120000_BLANK/  ← Permanent blank backup
```

**After 1st daily exit:**
```
backups/
├── dolibarr_backup_20251025_120000_BLANK/  ← Permanent blank backup  
└── dolibarr_backup_20251026_180000/        ← 1st daily backup
```

**After 4th daily exit:**
```
backups/
├── dolibarr_backup_20251025_120000_BLANK/  ← Permanent blank backup
├── dolibarr_backup_20251027_180000/        ← 3rd daily backup 
├── dolibarr_backup_20251028_180000/        ← 2nd daily backup
└── dolibarr_backup_20251029_180000/        ← 1st daily backup (newest)
```

**After 5th daily exit (cleanup occurs):**
```
backups/
├── dolibarr_backup_20251025_120000_BLANK/  ← Permanent blank backup
├── dolibarr_backup_20251028_180000/        ← 3rd daily backup
├── dolibarr_backup_20251029_180000/        ← 2nd daily backup  
└── dolibarr_backup_20251030_180000/        ← 1st daily backup (newest)
```
*Note: The 20251027 backup was removed as it was neither newest 3 nor oldest.*

8. **Container shutdown:** Stop services safely

## Backup Structure

### Backup Directory Layout

Each backup contains:

```
dolibarr_backup_YYYYMMDD_HHMMSS[_BLANK]/
├── database.sql              # Complete MySQL/MariaDB dump
├── documents.tar.gz          # Compressed archive of all files
├── config/                   # Configuration directory
│   └── conf.php             # Dolibarr configuration file
└── backup_info.txt          # Backup metadata and information

Compliance COOS directory (separate):

```
coos_backup/
├── COPYING
├── COPYRIGHT
├── ChangeLog
├── MANIFEST.md
└── TRACE.md
```
```

### File Descriptions

**database.sql:**
- Complete MySQL dump using `mysqldump`
- Includes all tables, data, indexes, triggers
- UTF8MB4 character set preserved
- Can be restored with standard MySQL tools

**documents.tar.gz:**
- Compressed archive of `/var/www/html/documents/`
- Contains all uploaded files, generated documents
- Preserves directory structure and permissions
- Uses gzip compression for space efficiency

**config/conf.php:**
- Complete Dolibarr configuration file
- Database connection settings
- Module configurations
- Security settings and keys

**backup_info.txt:**
- Backup creation timestamp
- File sizes and statistics
- System information at backup time
- Dolibarr version and modules
- Database schema version

## Restore System

### Complete System Restore

**Purpose:** Restore entire Dolibarr system from backup

**Command:**
```bash
./restore_dolibarr.sh /path/to/backup/directory
```

**Process:**
1. **Backup validation:** Verify backup integrity
2. **System shutdown:** Stop all containers safely  
3. **Volume cleanup:** Clear existing data
4. **Database restore:** Import SQL dump
5. **File restoration:** Extract documents archive
6. **Configuration restore:** Apply saved settings
7. **System restart:** Start containers with restored data
8. **Validation:** Verify system functionality

### Restore Examples

**Restore from recent backup:**
```bash
# List available backups
ls -la backups/

# Restore from specific backup
./restore_dolibarr.sh backups/dolibarr_backup_20251027_183000
```

**Factory reset (restore to blank state):**
```bash
# Find your blank backup
ls -la backups/ | grep BLANK

# Restore to clean installation state
./restore_dolibarr.sh backups/dolibarr_backup_20251025_120000_BLANK
```

**Emergency restore after corruption:**
```bash
# System won't start - restore from most recent
./restore_dolibarr.sh backups/$(ls -t backups/ | head -1)
```

## Backup Management Commands

### List and Inspect Backups

```bash
# List all backups with sizes
ls -lah backups/

# Show backup details with human readable sizes
du -sh backups/*/

# Find blank backup
ls -la backups/ | grep BLANK

# Count total backups
ls -1 backups/ | wc -l
```

### Backup Information

```bash
# View backup metadata
cat backups/dolibarr_backup_20251027_183000/backup_info.txt

# Check backup integrity
tar -tzf backups/dolibarr_backup_20251027_183000/documents.tar.gz > /dev/null
echo $?  # Should return 0 if valid

# Check database dump
head -20 backups/dolibarr_backup_20251027_183000/database.sql
```

### Manual Cleanup

```bash
# Remove specific backup (use caution!)
rm -rf backups/dolibarr_backup_20251025_150000

# Emergency cleanup - keep only newest 2 + blank
# (This overrides the retention policy temporarily)
cd backups/
ls -t | grep -v BLANK | tail -n +3 | xargs rm -rf
```

## Advanced Backup Features

### Backup Validation

All backups are automatically validated:

**Database Validation:**
- SQL dump syntax checking
- Character set verification
- Size consistency checks

**Document Validation:**
- Archive integrity testing
- File count verification  
- Compression validation

**Configuration Validation:**
- PHP syntax checking
- Required parameters present
- Security settings preserved

### Backup Compression

**Documents:** Automatically compressed with gzip
- **Compression Ratio:** Typically 60-70% size reduction
- **Performance:** Fast compression/decompression
- **Compatibility:** Standard gzip format

**Database:** Plain text SQL (not compressed)
- **Readability:** Easy to inspect and modify
- **Compatibility:** Works with any MySQL/MariaDB
- **Size:** Larger but more reliable

### Backup Security

**File Permissions:**
- Backups created with restricted permissions (600)
- Only owner can read/write backup files
- Directory permissions prevent unauthorized access

**Data Integrity:**
- Checksums calculated during creation
- Validation performed before restore
- Corruption detection built-in

## Monitoring and Alerts

### Backup Success Monitoring

Monitor backup success via:

**Exit Codes:**
- `0` - Success
- `1` - Backup creation failed  
- `2` - Retention cleanup failed
- `3` - Container operations failed

**Log Analysis:**
```bash
# Check recent backup status
tail -50 /var/log/dolibarr_backup.log

# Monitor backup sizes over time
ls -la backups/ | awk '{print $5, $9}' | sort
```

### Storage Monitoring

```bash
# Check total backup storage usage
du -sh backups/

# Monitor available disk space
df -h /workspaces/dolibarr/

# Alert if backups exceed size threshold
BACKUP_SIZE=$(du -s backups/ | cut -f1)
if [ $BACKUP_SIZE -gt 1000000 ]; then
    echo "WARNING: Backups using >1GB storage"
fi
```

### Automated Monitoring

**Cron Integration:**
```bash
# Add backup monitoring to crontab
0 19 * * * /workspaces/dolibarr/docker-deploy/daily_exit.sh && echo "Backup successful $(date)" || echo "Backup failed $(date)"
```

**Health Checks:**
```bash
# Create backup health check script
#!/bin/bash
LATEST_BACKUP=$(ls -t backups/ | head -1)
BACKUP_AGE=$(find backups/$LATEST_BACKUP -mtime +1)
if [ -n "$BACKUP_AGE" ]; then
    echo "WARNING: Latest backup older than 1 day"
    exit 1
fi
```

## Disaster Recovery

### Complete System Loss

**Scenario:** Codespace deleted, containers corrupted, volumes lost

**Recovery Steps:**
1. **Create new Codespace** from repository
2. **Navigate to setup:** `cd /workspaces/dolibarr/docker-deploy`
3. **Recreate system:** `./recreate_dolibarr.sh`
4. **Copy backups** from external storage (if available)
5. **Restore data:** `./restore_dolibarr.sh backups/[latest]`
6. **Verify restoration:** Access http://localhost:8080

### Partial Data Loss

**Scenario:** Database corrupted but files intact

**Recovery Steps:**
1. **Stop system:** `docker compose down`
2. **Restore database only:** 
   ```bash
   docker compose up -d db
   docker compose exec db mysql -u root -prootpassword dolibarr < backups/[latest]/database.sql
   ```
3. **Start system:** `docker compose up -d`

### Configuration Recovery

**Scenario:** Configuration corrupted but data intact

**Recovery Steps:**
1. **Extract config from backup:**
   ```bash
   cp backups/[latest]/config/conf.php ./temp_conf.php
   ```
2. **Stop containers:** `docker compose down`
3. **Replace configuration:**
   ```bash
   docker compose up -d app
   docker compose exec app cp temp_conf.php /var/www/html/conf/conf.php
   ```
4. **Restart system:** `docker compose restart`

**Weekly Reviews:**

**Monthly Maintenance:**

- ✅ Update backup documentation
- ✅ Consider external backup storage options

### Storage Management

**Codespace Limits:**
- Monitor total storage usage
- GitHub Codespaces have storage limits
- Consider external backup storage for long-term retention

**External Storage Options:**
```bash
# Upload backups to external storage
rsync -av backups/ user@external-server:/backup/dolibarr/

# Download backups from external storage
rsync -av user@external-server:/backup/dolibarr/ backups/
```

### Security Considerations

**Backup Security:**
- Backups contain sensitive business data
- Ensure proper file permissions (600)
- Consider encryption for external storage
- Regular security audits of backup access

**Access Control:**
- Limit access to backup directory
- Use strong passwords for database access
- Regular rotation of system passwords
- Monitor backup access logs

This comprehensive backup system ensures your Dolibarr data is always protected while maintaining efficient storage usage and providing reliable disaster recovery capabilities.
